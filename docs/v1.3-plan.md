## M1 偏好持久化（0.5 天编码 + 0.5 天测试）

### 现状缺陷（已实测）
- 主题手动切换后重启即丢（每次启动跟随系统）；
- 窗口固定 1200×800，位置/大小/最大化不记忆；
- 缩放级别不记忆。

### 设计

**存储位置**：主进程 `userData/preferences.json`（单一事实源）。不放在 localStorage，因为窗口尺寸和缩放归主进程管，拆两个存储会出现双主问题。侧边栏折叠状态继续留在 localStorage（纯渲染进程 UI 态，已有测试覆盖，不动）。

**新模块 `lib/preferences.js`**（纯 Node，可单测）：

```js
const DEFAULTS = {
  theme: 'system',            // 'system' | 'light' | 'dark'
  windowBounds: null,         // { x, y, width, height, maximized } | null
  zoomLevel: 0,               // Electron 对数刻度
};

loadPreferences(filePath)   // 读取 + 容错：文件缺失/JSON 损坏/字段非法 → 与默认值合并
savePreferences(filePath, prefs) // 全量写回
clampBounds(bounds, displays)    // 恢复前校验：必须与某个已连接显示器相交，否则返回 null
```

要点：读取时逐字段校验类型与取值范围（theme 白名单、zoomLevel 限 ±7.27、bounds 数值非 NaN）；损坏文件不抛错、直接回落默认值并重写。

**IPC**（preload 新增）：
- `prefs:getAll`（invoke）→ 渲染进程启动时取一次；
- `prefs:set`（send，局部补丁）→ 主进程合并后**防抖 300ms** 写盘（避免 resize 期间刷盘）。

**集成点**：
1. **主题**：`toggleTheme()` 与新的"跟随系统"菜单项都改为写 `prefs:set { theme }`；启动时 init 流程改为 `prefs:getAll` → `theme === 'system'` 则走 `getSystemTheme()` 并保持 `followsSystemTheme=true`，否则直接应用固定主题。`theme:systemChanged` 事件只在 `theme === 'system'` 时生效。视图菜单新增「跟随系统主题」可勾选项（勾选时清回 'system'）。
2. **窗口**：`mainWindow.on('close')` 时记录 bounds + isMaximized → `prefs:set`；`createWindow()` 先 `loadPreferences` → `clampBounds` 校验通过则用恢复值创建，否则用 1200×800 默认；`maximized: true` 时先以恢复尺寸创建再 `maximize()`。
3. **缩放**：`did-finish-load` 先 `setZoomLevel(prefs.zoomLevel)` 再发送给渲染进程（顺序不能反，否则状态栏先闪 100%）；`changeZoom`/`zoom-changed` 两处同步 `prefs:set`。
4. **菜单**：文件菜单不变；视图菜单加「跟随系统主题」。

### 验收标准
- [ ] 切暗色 → 退出 → 启动仍为暗色（且不随系统翻转）；
- [ ] 「跟随系统」勾选后 → 主题随系统变化且重启保持勾选；
- [ ] 窗口拖到副屏 + 最大化 → 重启还原位置与最大化；副屏拔掉后重启回落默认位置（不出现不可见窗口）；
- [ ] 缩放 150% → 重启保持 150%，状态栏显示 150%；
- [ ] 手动删除/损坏 preferences.json → 正常启动，全部默认值；
- [ ] `lib/preferences.js` 单测：缺省加载、损坏 JSON、非法字段、bounds 越界裁剪、读写回环（≥8 个用例）。

## M2 大纲/目录面板（1.5 天编码 + 0.5 天测试）

### 设计

**侧边栏改为双 Tab**：`文件` ｜ `大纲`（默认停在文件页，保留 Ctrl+Shift+E 整体开关；视图菜单新增「大纲」项，快捷键 `Ctrl+Shift+O` 切到大纲页）。

**解析器 `lib/outline.js`**（纯函数，可单测）：

```js
extractOutline(markdown) → [{ level: 1-6, text, line }]  // line 为 1-based 行号
```

- 逐行扫描 `^(#{1,6})\s+(.+?)\s*#*$/`；
- **围栏感知**：``` 与 ~~~ 开关状态跟踪（含语言标记行），围栏内的 `#` 行不算标题；
- 不支持 setext 标题（`===` 下划线式）——v1.3 明确不做，文档标注限制；
- front matter 的 `---` 块天然不含 `#` 标题行，无需特判（title: 等行不匹配正则）。

**UI（index.html + app.js + style.css）**：
- sidebar-header 下方加 tab 条（两个按钮，`role=tab` + `aria-selected`）；
- 大纲列表：按 level 缩进（level 1 顶格、6 级最深），标题文字 `text-overflow: ellipsis`，行高与文件树一致；
- 空状态："当前文档没有标题"。

**刷新**：`change` 事件防抖 300ms 重建列表（重建后保持列表 scrollTop）；文档切换即刷新。

**跳转**：
- 源码模式：`editor.setSelection([line, 1], [line, 1])` —— Toast UI setSelection 自带 scrollIntoView（已验证）；
- 所见即所得模式：按**出现顺序**配对——`doc.descendants` 收集 ww 中的 heading 节点序列，与 markdown 标题序列逐个配对，取第 n 个 heading 节点的 pos 调 `editor.setSelection(pos + 1, pos + 1)`；两序列数量不一致时（罕见）降级为按文本匹配，仍失败则 toast 提示切换到源码模式。

**当前标题高亮**：`caretChange`（已有）时用光标行号在 outline 数组中二分找"最后一个 ≤ 光标行"的标题，列表加 `.active` 并 `scrollIntoView({ block: 'nearest' })`。

### 验收标准
- [ ] 6 级标题文档：层级、顺序、行号全部正确；
- [ ] 代码围栏内的 `# 注释` 不出现在大纲；
- [ ] 源码模式点击大纲项 → 光标落到对应行且编辑器滚动到位；
- [ ] 所见即所得模式点击 → 光标落到对应标题；
- [ ] 光标移动时当前章节高亮跟随；增删标题后 ≤ 300ms 刷新；
- [ ] 1000 行多标题文档无明显卡顿（重建 < 50ms）；
- [ ] `lib/outline.js` 单测 ≥ 10 个用例（围栏、缩进、行号、空文档、纯代码块文档）；
- [ ] 冒烟测试新增大纲断言（见 M4）。

## M3 打印 + 导出 PDF / 导出 HTML（1.5 天编码 + 0.5 天测试）

### 设计

**独立打印窗口 `renderer/print.html`**（关键决策：不在主窗口直接打印）。
理由：① 主窗口当前可能是源码模式/暗色主题，打印需要统一"白底、无工具栏"的渲染态；② `editor.getHTML()` 在源码模式不可靠；③ Mermaid 需要异步渲染时机，独立窗口可以安心等待。Typora/Obsidian 的打印也都是独立渲染管线。

流程（主进程 `export:*` 三个 IPC handler 共用一条管线）：

```
渲染进程 menu:export → invoke('export:pdf'|'export:html'|'print', markdown)
  → 主进程创建隐藏 BrowserWindow，加载 print.html?theme=print
  → print.html 内创建 Toast UI Editor（隐藏工具栏/模式条），setMarkdown
  → 等待全部 .mermaid-diagram[data-mermaid-rendered] 就绪（超时 5s 兜底继续）
  → notify 主进程 ready
  → PDF:    printToPDF({ printBackground: true, pageSize: 'A4' })
  → HTML:   取预览区 innerHTML + 内联 print.css + tui CSS 生成单文件
  → 打印:   printWin.webContents.print({ silent: false })
  → 关闭打印窗口，返回 { ok, path? } 给渲染进程 toast
```

**print.css**（打印态样式，同时服务 PDF 与纸张）：
- 强制白底黑字、正文 12pt/1.6；
- `pre, blockquote, table, .mermaid-diagram { break-inside: avoid; }`（代码块不跨页截断）；
- `h1-h6 { break-after: avoid; }`（标题不孤行页尾）；
- 链接显示为正文色（打印不区分色）。

**文件名与保存对话框**：
- PDF/HTML：`showSaveDialog`，默认路径=当前文档目录，默认名=当前文件名换扩展（未命名.md → 未命名.pdf）；
- 成功后 toast「已导出到 xxx」+ `shell.showItemInFolder` 定位文件；
- 打印：系统打印对话框，无文件操作。

**菜单**：文件菜单新增「打印… Ctrl+P」「导出 ▸ PDF… / HTML…」；编辑期间导出走当前 markdown 快照（导出过程用户继续编辑不影响结果）。

**安全**：print.html 不挂 preload（无需 IPC 能力）、contextIsolation 开启、仅加载本地资源。

### 验收标准
- [ ] 含 Mermaid 的文档导出 PDF：图表为渲染后的 SVG（非源码文本），白底 A4 分页正常；
- [ ] 长代码块跨页时不被截断成两半（break-inside 生效）；
- [ ] 导出 HTML 为**单文件**，双击浏览器打开即含样式与 Mermaid 图；
- [ ] 暗色主题下导出，PDF/HTML 仍是白底（不导出暗色）；
- [ ] 未命名文档导出默认名「未命名.pdf」；导出成功后资源管理器定位到文件；
- [ ] 无标题纯文本文档导出不报错；空文档导出 PDF 不报错；
- [ ] 无头测试：print 窗口渲染 → printToPDF 返回 `%PDF` 头且 > 10KB；HTML 导出含 `<svg`（Mermaid 已渲染）。

| 风险 | 对策 |
| --- | --- |
