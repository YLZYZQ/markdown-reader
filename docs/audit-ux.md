# 问题文档：操作体验审查

审查方式：无头 Electron 审计脚本（`test/audit-electron.js`，窗口不显示、不抢焦点）+ 全功能遍历操作。
审查日期：2026-08-30。基线版本：v1.1.0（commit 45a34a3）。

> 状态标记：✅ 已修复 ｜ 🔧 已改善（行为记录） ｜ ⏳ 记录暂不修（含理由）

## U1【严重】查找定位落在错误位置

**现象（实测证据）**：源码模式下文档含 2 处 `alpha`，打开查找输入 `alpha` 后按 Enter：

- 高亮落在了右侧**只读预览副本**上（`window.getSelection()` 的锚点位于 `.toastui-editor-md-preview` 内），而不是左侧可编辑的源码区。
- 计数显示 `1/2`（按 Markdown 源计算），但 `window.find` 实际在"源码 + 预览"两份文本中循环，用户要按 4 次才能回到起点——计数与实际导航完全对不上。
- 查找输入框聚焦时按 Enter，搜索起点在面板自身，理论上会先"匹配到输入框里的查询词"；侧边栏文件名也会被卷入循环。

**根因**：`app.js findInEditor()` 使用 `window.find()`，它搜索整个文档（含预览、面板、侧边栏），且起点取决于当前 DOM 选区位置。

**修复**：改为基于 ProseMirror 的精确查找导航——按当前模式取"可见文本"（源码模式 = Markdown 源；所见即所得模式 = 渲染文本 + PM 位置映射），匹配、计数、高亮、滚动全部对齐；替换仍操作 Markdown 源。✅

## U2【严重】Ctrl+Shift+S（另存为）在编辑器内无效

**现象（实测证据)**：向编辑器发送真实 `Ctrl+Shift+S` 按键后，ProseMirror 将其标记为 `defaultPrevented=true`，并且选中文字被加上了**删除线**（`~~内~~容`）——Toast UI 的 `Strike` 键位同时绑定了 `Mod-S`（即 Ctrl+Shift+S）。菜单加速键被吞，"另存为"永不触发。这与当初 Ctrl+S 失效是同一根因，v1.0.4 只拦截了 Ctrl+S。

**修复**：`main.js` 的 `before-input-event` 同步拦截 `Ctrl+Shift+S`，转发 `menu:saveAs`。✅

## U3【严重】状态栏光标位置显示错误值

**现象（实测证据）**：

- 源码模式：把光标定位到第 5 行（`setSelection([5,1])`，已证实 Toast UI 源码模式使用 1-based `[行,列]`），状态栏仍显示 `第1行 第1列`。
- 所见即所得模式：光标在文档末尾，显示 `第3行 第2列`，实际列号应为第 8 列——当前实现拿 DOM 文本节点的 `range.startOffset` 当作整篇 Markdown 的偏移量换算，纯属错误。
- 编辑器未聚焦时（例如在查找框中选中文本），会把查找框里的选区当作文档光标显示。
- 跟踪用 `requestAnimationFrame` 循环每秒 60 次调用 `editor.getMarkdown()`（全文档序列化），纯性能浪费；`pmView` 变量是死代码。

**修复**：改用 Toast UI `caretChange`/`focus`/`blur` 事件驱动；源码模式直接用 `getSelection()` 返回的 `[行,列]`；所见即所得模式用 ProseMirror `$from.index(0)`/`$from.parentOffset` 换算块行号与列号；编辑器未聚焦时清空显示；删除 rAF 循环。✅

## U4【中】缩放百分比显示公式错误，且缩放后永不更新

**现象（实测证据)**：

- 发送缩放级别 1（真实含义 **120%**，Electron 缩放因子 = 1.2^level），状态栏显示 `110%`——公式 `(1 + level*0.1)` 错误。
- `main.js` 监听的 `zoom-commit` 事件**在 Electron 中不存在**（electron.d.ts 中 0 处，实际事件名为 `zoom-changed`），菜单缩放（Ctrl+滚轮/菜单项）后状态栏永不刷新，仅启动 500ms 后显示一次 `100%`。

**修复**：公式改为 `1.2^level`；监听 `zoom-changed`（Ctrl+滚轮）；菜单缩放项改为自定义处理（`setZoomLevel` 后主动通知渲染进程）；初始值改在 `did-finish-load` 后发送。✅

## U5【中】编辑器内按 Escape 无法关闭查找面板

**现象（实测证据）**：查找面板打开时，焦点在编辑器内按 Escape，面板保持打开（`escapeClosesFind=false`）。Escape 只绑定在两个输入框上。

**修复**：增加全局 Escape 处理——面板打开时任意位置按 Escape 关闭面板。✅

## U6【中】"全部替换"后滚动位置丢失

**现象**：`replaceAllMatches()` 调用 `editor.setMarkdown(nextContent)`，Toast UI 的 setMarkdown 会把编辑器滚动重置到顶部，长文档中执行全部替换后丢失阅读位置。（审计脚本对该项采样时机不佳，结论以修复后的回归断言为准。）

**修复**：替换前记录滚动位置，替换后恢复。✅

## U7【中】"保存"菜单项不显示 Ctrl+S 快捷键

**背景**：v1.0.4 修复 Ctrl+S 时把菜单项的 accelerator 移除了（避免与拦截逻辑冲突），副作用是菜单上看不到 Ctrl+S 提示，帮助对话框成了唯一入口。

**修复**：使用 Electron 的 `registerAccelerator: false`——菜单显示 `Ctrl+S` 字样，但不注册系统加速键（实际按键仍由 `before-input-event` 拦截，两条路径不冲突）。✅

## U8【低】拖拽拒绝提示缺少 .mdown

**现象**：拖入不支持的文件提示"仅支持 Markdown 文件 (.md/.markdown/.txt)"，但程序实际还支持 `.mdown`（打开对话框与侧边栏均含），提示文案与真实能力不一致。

**修复**：文案补全为 `.md/.markdown/.mdown/.txt`。✅

## U9【中】主题切换丢失光标/撤销历史；系统主题未变时也重建

**现象**：`applyTheme()` 无条件 `rebuildEditor()`：光标与选区丢失、撤销历史清空；系统主题变化通知即使主题值与当前相同也会重建整个编辑器（可感知的闪烁）。

**修复**：主题值未变化时跳过重建；重建时保存/恢复选区（`getSelection`/`setSelection`，两种模式格式各自兼容）。✅

## U10【中】文件被外部程序修改无任何提示（数据风险）

**现象**：文档在磁盘上被其他编辑器修改后，应用毫无感知，此时按保存会**无提示覆盖外部修改**，造成数据丢失。同类阅读器（Typora/Obsidian）均有外部变更检测。

**修复**：主进程监听当前文档所在目录（`fs.watch`），用自身写入时间戳防止保存自触发误报；检测到外部变更向渲染进程发通知，状态栏+toast 提示"文件已在磁盘上被修改"。✅

## U11【中】打开超大文件无保护

**现象**：`readDocument()` 无大小上限，误打开数 GB 的 `.txt` 会把整份内容读进渲染进程，界面假死甚至崩溃。

**修复**：主进程读取前检查大小，超过 30 MB 返回明确错误"文件过大（超过 30 MB）"。✅

## U12【中】UTF-16 编码文件打开即乱码

**现象**：Windows 记事本"Unicode"保存的文件（UTF-16 LE BOM）按 utf8 硬解码，打开是乱码且可被用户无意保存，破坏内容。

**修复**：按 BOM 识别编码——UTF-16 LE/BE 正确解码为文本（保存时统一写 UTF-8）；UTF-8 BOM 剥离（避免 `\uFEFF` 混入字数统计与查找）。✅

## U13【低】帮助/关于对话框未判空主窗口

**现象**：窗口关闭瞬间点击菜单触发 `dialog.showMessageBox(mainWindow, …)`，`mainWindow` 可能为 null 导致主进程异常。

**修复**：判空保护。✅

## U14【低】查找计数显示口径不统一

**现象**：未开始导航时显示 `2 处`，导航后显示 `1/2`，同一面板两种口径；无结果时无视觉强调。

**修复**：保持"未导航显示 `N 处`、导航后显示 `i/N`"的惯例口径（与 VS Code 一致）；查询无结果时显示 `0 处` 并以红色加粗强调（亮暗主题各自取色）。✅
