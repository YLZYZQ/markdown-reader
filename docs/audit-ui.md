# 问题文档：UI 视觉审查

审查方式：无头渲染截图（亮/暗主题 × 源码/所见即所得模式 × 查找面板/右键菜单/侧边栏状态），配合计算样式（`getComputedStyle`）比对主题变量。
审查日期：2026-08-30。基线版本：v1.1.0（commit 45a34a3）。

> 状态标记：✅ 已修复 ｜ ⏳ 记录暂不修（含理由）
> 截图伪影说明：隐藏窗口截图中 CSS 动画会被冻结在起始帧（右键菜单截图文字呈半透明即此伪影），均已通过计算样式与可见窗口复核排除，不计为问题。

## V1【严重】暗色主题下 Mermaid 图表为白底黑框

**证据**：暗色主题源码模式下，预览区 `.mermaid-diagram` 计算背景色为 `rgb(255,255,255)`（截图 `s1` 侧证：所见即所得模式为正确的 `#121212`，源码模式为刺眼白块）。

**根因**：`style.css` 两处使用 `var(--editor-bg, #fff)`，而 `--editor-bg` 变量**从未在任何主题中定义**，永远落到 `#fff` 回退值；暗色仅对所见即所得的 NodeView 有显式 `#121212` 覆盖，漏掉了源码模式预览。

**修复**：在亮/暗主题中定义 `--editor-bg`（`#ffffff` / `#121212`），两处引用改用变量。✅

## V2【中】暗色主题次要文字对比度不足

**证据**：`--muted` 暗色取值 `#6a6a6a`，在状态栏 `#1f1f1f`、标题栏 `#202020`、侧边栏 `#202020` 上的对比度约 2.9~3.2:1，低于 WCAG AA 小字要求（4.5:1）；状态栏字号仅 11.5px，截图 `s1` 中"尚未打开文档""所见即所得模式"等文字明显发暗难读。

**修复**：暗色 `--muted` 调整为 `#9a9a9a`（对上述底色对比度 ≥ 5:1），亮色 `#656d76` 维持不变（对比度约 4.9:1，达标）。✅

## V3【中】查找面板在暗色主题下阴影/边框层级不清

**证据**：暗色下 `.find-panel` 背景与编辑器背景接近（`#202020` vs `#191919`），仅靠 1px 边框区分，浮层感弱。

**修复**：为浮层（查找面板、右键菜单）在暗色主题下提升边框亮度并加入主题化阴影变量，增强浮层与底层的层次。✅

## V4【低】状态栏信息缺少分隔

**证据**：状态栏右侧"第1行 第1列 / 24 字 / 110%"三项以 14px 间距排列，无视觉分隔符，小字号下易连读（截图 `s1`）。

**修复**：右侧行/列、字数、缩放三项之间加入细分隔点。✅

## V5【低】侧边栏激活文件高亮依赖 color-mix 透明度偏淡

**证据**：`--accent 15%` 混合后的激活项底色在亮色主题下较淡，当前文件辨识度一般。

**修复**：激活态底色提高到 18% 并保持文字加粗 accent 色，同时给非激活文件行补 `:focus-visible` 轮廓（键盘可达性）。✅

## V6【低】拖拽遮罩图标与文案间距偏大、遮罩边框圆角过大

**证据**：`drop-inner` 48px/64px 内边距 + 16px 圆角在 1280×860 视口下显得松散（未截图定案，按布局参数评估）。

**修复**：内边距收窄为 36px 52px、圆角 12px，观感更紧凑。✅
